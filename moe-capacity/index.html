专家排满以后，token 去哪儿？

路由器为 token 选专家，专家却可能只有固定的处理容量。用 12 个 token 和 3 名专家看看：即使总空位足够，一位专家也可能先被挤满。

先做一个对照

先提高首选集中度，让大多数 token 都首选 A。对比「留作未处理」和「尝试改派」，再把每位专家的容量缩到 3，观察改派还能救回多少。

原理与研究练习

每个 token 有确定的首选和备选顺序，按输入顺序处理。每位专家都只能接收指定数量。改派模式在首选已满时查找下一位有空位的专家。这个简化规则忽略专家输出质量、专家间通信与批大小变化。

Switch Transformer 展示了 top-1 路由、容量与负载均衡的关系。改变输入批次分布时，可同时记录未处理比例、专家利用率和实际任务质量。
